# Class 2 업체·품목군 비교분석 명세

> 상태: 구현 가능한 신규 제품 명세
> 사용자: 일반 공개 사용자, 인증 기업 사용자, 내부 운영자
> 전제: [Class 2 재구축 결정](../decisions/class2-rebuild-decision.md)과 [Class 2 웹 스택](../decisions/class2-web-stack.md)을 따른다.

## 제품 정의

Class 2는 보고된 의료기기 공급 활동을 품목군·품목명 단위로 비교하고, 인증된 기업에는 자사 포트폴리오와 익명 동종업체군의 차이를 보여주는 일반 웹 서비스다. MCDM, 임상 영향, 공급 위험 점수, 실명 업체 간 비교 서비스가 아니다.

## 제품 원칙

- **Locked decision** — 품목군과 품목명을 다중 검색한다.
- **Locked decision** — 품목별 개별 결과와 선택 포트폴리오 요약을 분리한다.
- **Locked decision** — 보고 거래 활동, 공급 수량, 공급자 수, 수령자 수, 수령자 업종 구성, 광역 지역 구성을 제공한다.
- **Locked decision** — `최종단 추적` 대신 `관측된 유통 도달 구조`를 제공한다.
- **Locked decision** — 공개 업체 비교는 실명 업체 쌍이 아니라 익명 동종집단 비교다.
- **Locked decision** — 공개 억제·비식별·결측 안내는 결과의 일부다.
- **Confirmed fact** — 현재 혁신 시안은 단일 품목명 검색과 기업군 3단계 입력에 묶여 있어 다중 비교 계약을 충족하지 않는다.

## 사용자 모드

### 일반 공개

가능:

- 품목군과 품목명 혼합 검색·다중 선택
- 선택별 월별 보고 거래 활동
- 원본/낱개 수량과 유효률
- 활성 공급자·수령자 수
- 수령자 업종·광역 지역 구성
- 관측된 다음 유통 단계 구성
- 승인된 품목별 공급자 집중도
- 데이터 범위·결측·억제 설명

불가:

- 회사명·사업자번호·업체일련번호 검색
- 업체 A와 업체 B의 실명 비교
- 정확한 업체별 금액·수량·순위
- 원시 거래 경로와 행 단위 export

### 인증 기업

추가 가능:

- 검증된 자사 취급 품목 포트폴리오
- 자사 월별 활동과 익명 동종집단 범위 비교
- 품목별 자사 비중·상대 구간
- 동종집단 기준의 공급자·수령자 구성 비교

조건:

- 자사 소유권이 검증된 내부 업체 ID만 사용한다.
- 동종집단 결과가 공개 보호 규칙을 통과해야 한다.
- 자사 결과와 공개 결과의 캐시·감사·응답 스키마를 분리한다.

### 내부 운영

- 배치·품질·억제 사유·allowlist 검증
- 공개 전 집계 미리보기
- 감사 로그와 위험한 필터 조합 확인

## 검색 계약

### 품목 검색

- 하나의 검색창에서 `품목군`과 `품목명` 결과 유형을 명확히 구분한다.
- 공백·특수문자·대소문자/한글 정규화를 적용한다.
- prefix와 contains 검색을 지원한다.
- 최근·인기 추천은 공개 승인 집계만 사용한다.
- 선택 chip에 유형, 상위 분류, 명칭을 표시한다.
- **Proposed decision** — 최대 5개 선택, 최소 2자 검색, 20개 자동완성 결과.
- **Decision required** — 정확한 최대 선택 수와 동의어·오탈자 정책.

### 기간

- 완료된 월만 선택한다.
- 기본 기간과 최대 기간을 명시한다.
- 각 결과는 실제 포함 월, 갱신일, 누락 월을 반환한다.
- **Proposed decision** — 기본 최근 12개월, 최대 36개월. 생산 보유 전체 기간 직접 조회는 제공하지 않는다.

## 결과 정보 구조

### 1. 선택 조건 요약

- 선택 품목군/품목명
- 기간
- 보고 데이터 범위와 갱신일
- 공개/인증 모드
- 적용된 억제·구간화 정책 버전

### 2. 품목별 나란히 비교

각 선택 항목을 독립 열/카드로 표시한다.

- 월별 `tx_count`: 보고된 거래 활동
- `raw_supply_qty_sum`, `piece_qty_sum`: 서로 분리, 유효률 포함
- `amount_sum_clean`: 승인 시만, 금액 유효률 포함
- 활성 공급자 수
- 활성 수령자 수
- 품목별 공급자 집중도와 시장 정의
- 수령자 업종 구성
- 광역 지역 구성
- endpoint 미확인 비율

- **Locked decision** — 품목별 HHI를 합쳐 포트폴리오 HHI를 만들지 않는다.
- **Locked decision** — 증가를 수요 증가, 시장 성장, 매출 증가로 단정하지 않는다.

### 3. 선택 포트폴리오 요약

선택 항목 전체에 대한 구성비와 겹침을 보여준다.

- 품목별 거래 활동 비중
- 품목별 낱개 수량 비중은 단위가 비교 가능한 경우에만 제공
- 공급자·수령자 집합의 합집합 크기와 품목 간 겹침
- 업종·지역 구성
- 데이터 유효률 가중 요약

- **Locked decision** — 단위가 다른 품목의 수량 합계는 기본 총계로 표시하지 않는다.
- **Locked decision** — 포트폴리오 요약은 개별 품목 결과를 대체하지 않는다.

### 4. 관측된 유통 도달 구조

표시 가능:

- 제조·수입 → 유통 → 의료기관 등 관측된 다음 단계의 역할 비중
- 수령자 업종 구성
- 광역 지역 도달 구성
- 월별 고유 수령 업체 수
- endpoint 유형/의료기관 코드 미확인 비율

표시 금지:

- `최종단`, `완전한 유통 경로`, `최종 병원 도달률`
- 업체·병원 식별 경로
- 누락된 endpoint를 0 또는 미도달로 간주한 비율

### 5. 데이터 범위·결측·억제

모든 결과 화면에 다음을 둔다.

- 생산 방문과 서비스 배치의 데이터 기간
- 금액·수량·의료기관 코드 유효률
- `보고된 공급 활동`의 정의
- 억제된 셀 수와 억제 사유 범주
- 조건 확장 또는 다른 기간을 선택하는 방법

## 공개 데이터 보호

### 배치 규칙

1. 원시 행을 승인된 차원으로 서버에서 집계한다.
2. 직접 식별자를 제거한다.
3. 최소 셀 규칙을 적용한다.
4. 우세도 검사를 적용한다.
5. 보완 억제로 행·열 차감 복원을 막는다.
6. 기간·필터 간 차분 공격 위험을 검사한다.
7. 승인된 반올림·구간화 후 allowlist DTO로 적재한다.

### 응답 상태

| 상태 | 의미 | UI |
|---|---|---|
| `released` | 공개 규칙 통과 | 승인된 집계 표시 |
| `suppressed_small_cell` | 표본 부족 | 값 숨김, 범위 확장 안내 |
| `suppressed_dominance` | 소수 업체 우세 | 값 숨김, 이유 설명 |
| `suppressed_differencing` | 필터 조합 역추론 위험 | 일부 조합 비활성화 |
| `insufficient_coverage` | 결측·유효률 미달 | 수치 대신 coverage 안내 |
| `not_available` | 배치 미생성 | 가능한 기간·항목 제안 |

- **Confirmed fact** — 프로토타입의 `k >= 5`는 제안값이고 법적 안전선이 아니다.
- **Decision required** — 최소 셀·우세도·반올림·보완 억제의 운영 값.

## API 계약

### 공개 API

prefix 제안: `/public/v1/class2`

`GET /catalog/search?q=&types=item_group,item_name&limit=`

```json
{
  "items": [
    {"type":"item_group","id":"...","label":"...","parent_label":null}
  ]
}
```

`POST /comparisons`

입력:

```json
{
  "selections": [
    {"type":"item_group","id":"..."},
    {"type":"item_name","id":"..."}
  ],
  "period": {"from":"202501","to":"202512"}
}
```

출력:

- `selection_summary`
- `per_item_results[]`
- `portfolio_summary`
- `observed_reach`
- `coverage`
- `release_status`
- `data_version`, `policy_version`, `updated_at`

`GET /methodology`는 지표 정의, 시장 단위, 결측·억제 정책을 버전과 함께 반환한다.

### 인증 기업 API

prefix 제안: `/enterprise/v1/class2`

- `GET /me/portfolio?period=`
- `POST /me/peer-comparisons`
- `GET /me/cohort-definition/{id}`

응답은 자사 값과 익명 동종집단 범위를 구분하고, 동종집단 구성 규칙·표본 band·억제 상태를 포함한다.

### 금지 계약

- `company_name`, `business_registration_number`, 업체 serial, 병원 code, 주소, lot/serial은 공개 DTO에 존재할 수 없다.
- 공개 API는 임의 dimension/group-by 필드를 받지 않는다.
- 공개 API는 행 단위 export와 실명 company endpoint를 제공하지 않는다.

| 단계 | 입력 | 출력 |
|---|---|---|
| 검색 dimension | 마스터 3-key, 품목군·품목명 | 정규화 검색 사전, 동의어 버전 |
| 월 사실 | 정제 공급 행 | 업체×거래처×품목×월 사실 |

| 인증 비교 | 자사 검증 ID + 공개 보호된 cohort | 자사 vs 익명 동종집단 DTO |

## 테스트

### 집계 정확성

- 품목군과 품목명이 별도 ID·유형으로 유지된다.
- 거래 건수, 금액, 원본 수량, 낱개 수량이 별도 집계된다.
- 원본 수량과 낱개 수량의 유효 행 수가 별도 필드로 유지된다.
- `(source_version, source_row_id)` 중복이 거래 건수와 고유 공급자·수령자 수를 부풀리지 않는다.
- 정규화되지 않거나 불완전한 3-key, 일반 공급 음수값, 승인 전 반품·회수 행이 Class 2 집계에 유입되지 않는다.
- 서로 다른 품목 HHI가 합쳐지지 않는다.
- endpoint 결측이 `unknown`으로 보존되고 분모가 명시된다.

### 공개 보호

- 작은 셀, 우세 집단, 차분 가능한 조합 fixture가 각각 올바른 상태를 반환한다.
- 보완 억제 후 행·열 합으로 억제값을 복원할 수 없다.
- 공개 스키마 snapshot에 금지 필드가 없다.
- 여러 API 호출을 조합한 privacy budget/쿼리 제한 테스트를 통과한다.

### 인증·권한

- 미인증 사용자는 `/enterprise`에서 401이다.
- 기업 A 토큰으로 기업 B 자사 결과를 조회할 수 없다.
- 자사 검증이 끝나지 않은 계정은 동종집단 비교를 시작할 수 없다.
- 공개와 기업 캐시 키·DB role이 분리된다.

### UI·접근성

- 키보드로 다중 검색, chip 제거, 기간 선택, 비교표 읽기가 가능하다.
- 품목별 결과와 포트폴리오 요약이 별도 heading을 가진다.
- 억제·결측 상태가 색 이외의 텍스트로 설명된다.
- `최종단`, `임상 영향`, `공급 위험`, `기회 지도` 문구가 정식 화면에 없다.

## 완료 조건

- MCDM·Kraljic·임상 영향 서비스 계약에 의존하지 않는다.
- 다중 품목 검색과 품목별/포트폴리오 결과 분리가 동작한다.
- 일반 공개와 인증 기업 경계가 보안 테스트를 통과한다.
- 모든 공개 응답이 억제 상태, 결측·유효률, 기간, 데이터·정책 버전을 포함한다.
- 실명 업체 간 비교와 원시 경로가 없다.
- 원시 Excel을 요청 시 읽지 않고 사전 계산 데이터 제품만 조회한다.

## 결정 필요 사항

1. 공개 정책 임계값과 승인 책임자.
2. 동종집단 정의, 규모 band, 최소 표본.
3. 인증·자사 소유권 검증 절차.
4. 검색 최대 선택 수, 기본·최대 기간.
5. 공급 활동에 `출고`만 포함할지 반품·회수의 별도 시계열을 제공할지.
6. 공개 금액 지표를 제공할지, 제공한다면 반올림 단위와 최소 유효률.
